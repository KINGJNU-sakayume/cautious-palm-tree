# 업적 시스템

> 2026-09-26 개편 기준. 이전 문서(`achievements-review.md`)가 지적한 문제와 코드 분석에서 찾은 문제를 반영해 구조를 다시 짰습니다.

## 1. 기본 원칙: 업적은 기록에서 계산한다

이전 구조는 기록을 저장하는 순간에만, 그 기록과 **같은 카테고리**의 업적만 평가하고 결과(`isEarned`, `earnedAt`, `progress`)를 저장했습니다.
그래서 다음과 같은 문제가 있었습니다.

| 문제 | 예시 |
|------|------|
| 상위 카테고리 업적이 달성되지 않음 | '피트니스'에 기록 조건 업적을 만들면, 기록은 하위 카테고리(러닝 등)에만 쌓여 영원히 잠김 |
| 기록을 고치거나 지워도 반영 안 됨 | 1000km를 10km로 고쳐도 '1,000km' 업적이 그대로 달성 상태 |
| 업적을 나중에 만들면 기존 기록이 무시됨 | 이미 달린 기록이 있어도 '첫 걸음'이 다음 기록 전까지 잠김 |
| 연속 기록이 '오늘' 기준 | 지난 날짜로 7일치를 몰아서 기록하면 연속 업적이 달성되지 않음 |
| `single`이 새 기록만 봄 | 예전에 세운 최고 기록이 새로 만든 업적에 반영되지 않음 |
| 단위를 무시하고 더함 | 러닝에 '30 분'을 기록하면 km 누적에 30이 더해짐 |
| 메타 업적끼리 연결 불가, 삭제된 업적 참조 시 영구 잠김 | 목록에 있는 업적을 지우면 메타 업적을 달성할 방법이 없음 |

지금은 **업적 정의만 저장**하고, 기록·업적·카테고리가 바뀔 때마다 `evaluateAchievements()`(`src/utils/achievementEvaluator.js`)가 전체 기록을 날짜순으로 훑어 다시 계산합니다.

- **달성일(`earnedAt`)** = 조건이 처음 채워진 기록의 날짜. 10번째 기록의 날짜, 누적이 목표를 넘은 날, 연속 기록이 목표 일수에 닿은 날 등.
- 새로 달성한 업적은 알림으로 축하하고, 기록 삭제·수정으로 조건이 깨지면 "업적이 다시 잠겼어요"라고 알려 줍니다.
- 기록 삭제는 알림의 **되돌리기**로 바로 복구할 수 있습니다.

## 2. 범위

| 업적의 카테고리 | 세는 기록 |
|----------------|-----------|
| 있음 (예: 근력 운동) | 그 카테고리 **와 모든 하위 카테고리**(벤치 프레스, 스쿼트, 데드리프트)의 기록 |
| 없음 | 모든 기록 (미분류 기록 포함) |

카테고리를 삭제하면 그 안의 업적은 함께 삭제되고, 기록은 지워지지 않고 **상위 카테고리로** 옮겨집니다(최상위였다면 '미분류').

## 3. 조건 종류

| 조건 | 화면 이름 | 달성 기준 | 진행 표시 |
|------|-----------|-----------|-----------|
| `action` | 첫 기록 남기기 | 범위 안에 기록 1개 이상 | — |
| `count` | 기록 횟수 채우기 | 기록 N개 | `3 / 10회` |
| `cumulative` | 값을 모두 더해 목표 채우기 | 값의 합 ≥ 목표 | `42.5 / 100km` |
| `single` | 한 번에 목표 넘기기 | 기록 하나의 값 ≥ 목표 | `최고 12.4 / 21.1km` |
| `daily_cumulative` | 하루 합계로 목표 넘기기 | 같은 날 값의 합 ≥ 목표 | `하루 최고 1.5 / 2L` |
| `streak` | 며칠 연속 기록하기 | 가장 길게 이어진 연속 일수 ≥ N | `최장 5 / 7일` |
| `tag_match` | 특정 태그로 기록하기 | 태그가 붙은 기록 1개 | — |
| `tag_count` | 특정 태그로 여러 번 기록하기 | 태그가 붙은 기록 N개 | `2 / 5회` |
| `tag_set_complete` | 태그 목록 모두 모으기 | 목록의 모든 태그가 한 번 이상 | `4 / 23개` + 체크리스트 |
| `cross_category_cumulative` | 여러 카테고리 합산하기 | 카테고리별 집계(최고/합계/최근)의 합 ≥ 목표 | `240 / 300kg` |
| `composite` | 여러 조건 함께 채우기 | 모두 채우기(AND) 또는 하나만(OR) | `%` |
| `meta_count` | 업적 개수 채우기 | 범위 안의 (메타가 아닌) 업적 N개 달성 | `3 / 10개` |
| `meta_list` | 고른 업적 모두 달성하기 | 고른 업적 전부 달성 (메타 업적도 가능) | `2 / 5개` |
| `meta_clear` | 카테고리 업적 모두 달성하기 | 범위 안의 (메타가 아닌) 업적 전부 달성 — 나중에 추가한 업적도 포함 | `2 / 4개` |
| `manual` | 직접 체크하기 | 업적 화면에서 '달성했어요'로 날짜와 함께 체크 | — |

### 세부 규칙

- **단위**: 조건에 단위가 있으면 같은 단위의 기록만 셉니다. 환산할 수 있는 단위는 자동으로 바꿉니다
  (km·m, kg·g, L·ml, 시간·분·초, 원·만원). 단위 없이 남긴 기록은 조건의 단위로 봅니다.
- **태그**: `#`, 띄어쓰기, 영문 대소문자를 무시하고 비교합니다(`#한강 대교` = `한강대교`, `pr` = `PR`).
  기록할 때 그 카테고리 업적에 쓰이는 태그를 **추천 태그**로 보여 줍니다(숨김 업적 제외).
- **연속 기록**: '오늘부터 거꾸로'가 아니라 **기록 전체에서 가장 길게 이어진 기간**을 봅니다. 지난 날짜로 남긴 기록도 인정됩니다.
  (홈 화면의 '연속 기록' 숫자는 오늘 또는 어제까지 이어지고 있는 현재 연속 일수입니다.)
- **메타 업적**은 서로를 조건으로 쓸 수 있고, 더 이상 바뀌지 않을 때까지 반복 계산합니다. 순환 참조는 달성되지 않을 뿐 오류는 나지 않습니다.
  업적을 삭제하면 그 업적을 조건으로 쓰던 `meta_list`에서 자동으로 빠집니다.
- **잘못된 조건**(목표 0, 빈 태그 등)은 저장할 때 막고, 이미 저장된 경우에는 달성되지 않은 채 "조건 확인 필요"로 표시합니다.

## 4. 등급

등급은 난이도입니다. 업적을 만들 때 아래 기준을 안내합니다.

| 등급 | 기준 | 예 |
|------|------|----|
| 브론즈 | 처음 해 보는 일 | 첫 기록, 첫 5km |
| 실버 | 조금씩 쌓이는 습관 | 7일 연속, 10회, 벤치 1판 |
| 골드 | 꾸준함이 필요한 목표 | 30일 연속, 누적 100km, 3대 300 |
| 플래티넘 | 몇 달은 걸리는 큰 목표 | 하프 마라톤, 100일 연속, 만 페이지 |
| 다이아몬드 | 손에 꼽을 만한 기록 | 풀코스 마라톤, 3대 500, 1년 개근 |

이전의 '레전더리'는 다이아몬드로 합쳤습니다. 수동으로 입력하던 **희귀도 점수**는 개인용 앱에서 의미가 없어 없앴습니다.

## 5. 업적 정의 형식 (저장 형식 v2)

```js
{
  id: 'ach-run-004',
  title: '하프 마라톤',
  description: '한 번에 21.1km를 달려 보세요.',
  categoryId: 'cat-running',        // null이면 모든 기록
  tier: 'platinum',                 // bronze | silver | gold | platinum | diamond
  condition: { type: 'single', target: 21.1, unit: 'km' },
  isHidden: false,                  // 달성 전까지 이름·설명을 가림
  manualEarnedAt: '2026-09-26',     // manual 조건일 때만
}
```

없앤 필드: `type`(일회성/메타 — 조건 종류로 판단), `rarity`, `isEarned`·`earnedAt`·`progress`·`completedTags`(계산 값),
`progressFormat`·`expandTitle`·`completedStyle`·`incompleteStyle`(화면에서 쓰이지 않던 설정), `conditionDisplay`(설명과 겹쳐 설명으로 합침).

앱 전체 상태는 `{ categories, records, achievements, prefs }` 하나로 저장합니다. 즐겨찾기·대표 업적·카테고리 기본값처럼
따로 흩어져 있던 설정도 `prefs`로 모아 백업 파일에 함께 들어갑니다.

### v1 → v2 자동 이전

처음 열 때 이전 형식이면 자동으로 옮깁니다(`src/lib/appState.js`의 `migrateV1`).

- 기록과 카테고리는 그대로 유지합니다.
- 기본 업적 중 **사용자가 고치지 않은 것**은 새 목록의 내용으로 바꾸고, 새 목록에서 빠진 것은 지웁니다.
  고친 것과 직접 만든 업적은 그대로 두고 새 형식으로만 바꿉니다(레전더리 → 다이아몬드 등).
  어떤 업적을 고쳤는지는 이전 기본 목록의 지문(`src/data/legacyCatalog.js`)과 비교해 판단합니다.
- 사용자가 지운 기본 업적은 되살리지 않습니다. 새로 추가된 기본 업적은 필요한 카테고리가 남아 있을 때만 추가합니다.
- 저장된 데이터를 읽을 수 없으면 새로 시작하되, 원래 내용은 브라우저 저장소에 따로 보관하고 화면에 알려 줍니다.
