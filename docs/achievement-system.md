# 업적 시스템

> 2026-09-26 두 번째 개편 기준. 기록하기 화면과 달성 조건을 다시 점검해 고치고, 기본 카테고리를 33개에서 71개로,
> 기본 업적을 86개에서 786개로 늘렸습니다. 이전 개편 내용은 [10. 변경 내역](#10-변경-내역)에 있습니다.

## 1. 기본 원칙: 업적은 기록에서 계산한다

업적에는 **정의만 저장**하고, 달성 여부·달성일·진행도는 기록·업적·카테고리가 바뀔 때마다
`evaluateAchievements()`(`src/utils/achievementEvaluator.js`)가 전체 기록을 날짜순으로 훑어 다시 계산합니다.
그래서 지난 날짜로 기록을 남기거나, 기록을 고치거나 지워도, 업적을 나중에 만들어도 결과가 항상 맞습니다.

- **달성일(`earnedAt`)** = 조건이 처음 채워진 기록의 날짜. 10번째 기록의 날짜, 누적이 목표를 넘은 날, 연속 기록이 목표 일수에 닿은 날 등.
- 새로 달성한 업적은 알림으로 축하하고(한 번에 많이 달성하면 3개만 보여 주고 나머지는 개수로 알려 줌),
  기록 삭제·수정으로 조건이 깨지면 "업적이 다시 잠겼어요"라고 알려 줍니다.
- 기록 삭제는 알림의 **되돌리기**로 바로 복구할 수 있습니다.

## 2. 범위

| 업적의 카테고리 | 세는 기록 |
|----------------|-----------|
| 있음 (예: 근력 운동) | 그 카테고리 **와 모든 하위 카테고리**(벤치 프레스, 스쿼트, 데드리프트)의 기록 |
| 없음 | 모든 기록 (미분류 기록 포함) |

카테고리를 삭제하면 그 안의 업적은 함께 삭제되고, 기록은 지워지지 않고 **상위 카테고리로** 옮겨집니다(최상위였다면 '미분류').

## 3. 조건 종류

| 조건 | 화면 이름 | 달성 기준 | 진행 표시 |
|------|-----------|-----------|-----------|
| `action` | 첫 기록 남기기 | 범위 안에 기록 1개 이상 | — |
| `count` | 기록 횟수 채우기 | 기록 N개 (기준 값을 정하면 값이 기준 이상인 기록만) | `3 / 10회` |
| `days` | 기록한 날 수 채우기 | 기록한 날 N일 — 하루에 여러 번 기록해도 하루 (기준 값을 정하면 하루 합계가 기준 이상인 날만) | `12 / 30일` |
| `streak` | 며칠 연속 기록하기 | 가장 길게 이어진 연속 일수 ≥ N (기준 값을 정하면 하루 합계가 기준 이상인 날만 이어짐) | `최장 5 / 7일` |
| `period_streak` | 매주·매달 꾸준히 기록하기 | 한 주(한 달)에 M일 이상 기록한 주(달)가 N번 연달아 이어짐 | `최장 3 / 12주` |
| `cumulative` | 값을 모두 더해 목표 채우기 | 값의 합 ≥ 목표 | `42.5 / 100km` |
| `single` | 한 번에 목표 넘기기 | 기록 하나의 값 ≥ 목표 | `최고 12.4 / 21.1km` |
| `daily_cumulative` | 하루 합계로 목표 넘기기 | 같은 날 값의 합 ≥ 목표 | `하루 최고 1.5 / 2L` |
| `period_cumulative` | 한 주·한 달·한 해 합계로 목표 넘기기 | 달력의 한 주(월~일)·한 달·한 해 안에서 값의 합 ≥ 목표 | `한 달 최고 80 / 100km` |
| `tag_match` | 특정 태그로 기록하기 | 태그가 붙은 기록 1개 | — |
| `tag_count` | 특정 태그로 여러 번 기록하기 | 태그가 붙은 기록 N개 | `2 / 5회` |
| `tag_set_complete` | 태그 목록 모두 모으기 | 목록의 모든 태그가 한 번 이상 | `4 / 23개` + 체크리스트 |
| `category_count` | 여러 카테고리에 기록하기 | 기록이 있는 서로 다른 카테고리 N곳 (업적에 카테고리가 있으면 그 하위 카테고리) | `3 / 7곳` |
| `cross_category_cumulative` | 여러 카테고리 합산하기 | 카테고리별 집계(최고/합계/최근)의 합 ≥ 목표 | `240 / 300kg` |
| `composite` | 여러 조건 함께 채우기 | 모두 채우기(AND) 또는 하나만(OR) | `%` |
| `meta_count` | 업적 개수 채우기 | 범위 안의 (메타가 아닌) 업적 N개 달성, 등급을 정하면 그 등급 이상만 | `3 / 10개` |
| `meta_list` | 고른 업적 모두 달성하기 | 고른 업적 전부 달성 (메타 업적도 가능) | `2 / 5개` |
| `meta_clear` | 카테고리 업적 모두 달성하기 | 범위 안의 (메타가 아닌) 업적 전부 달성 — 나중에 추가한 업적도 포함 | `2 / 4개` |
| `manual` | 직접 체크하기 | 업적 화면에서 '달성했어요'로 날짜와 함께 체크 | — |

`days`·`period_streak`·`period_cumulative`·`category_count`와 기준 값, 등급 조건은 이번에 새로 생겼습니다.
"하루 2L 이상 7일 연속", "만 보 걸은 날 30일", "주 3회 운동 12주 연속", "월간 100km", "골드 이상 업적 20개"처럼
횟수만으로는 담기 어려웠던 목표를 그대로 적을 수 있습니다.

### 세부 규칙

- **단위**: 조건에 단위가 있으면 같은 단위의 기록만 셉니다. 환산할 수 있는 단위는 자동으로 바꿉니다
  (km·m·cm·마일, kg·g·파운드, L·ml·cc, 시간·분·초, 원·천원·만원·억, 페이지·쪽·p, 자·글자, 걸음·보, 회·번·개, kcal·칼로리).
  단위 없이 남긴 기록은 조건의 단위로 봅니다.
- **음수 값**은 합계·하루 합계·최고 기록 어디에도 세지 않습니다. 기록하기 화면에서도 받지 않습니다.
- **기간**: 한 주는 월요일부터 일요일까지, 한 달·한 해는 달력 그대로입니다. 연속 기간은 기록이 없는 주(달)가 끼면 끊깁니다.
- **태그**: `#`, 띄어쓰기, 영문 대소문자를 무시하고 비교합니다(`#한강 대교` = `한강대교`, `pr` = `PR`).
  기록할 때 그 카테고리 업적에 쓰이는 태그를 **추천 태그**로 보여 줍니다(숨김 업적 제외).
- **연속 기록**: '오늘부터 거꾸로'가 아니라 **기록 전체에서 가장 길게 이어진 기간**을 봅니다. 지난 날짜로 남긴 기록도 인정됩니다.
  (홈 화면의 '연속 기록' 숫자는 오늘 또는 어제까지 이어지고 있는 현재 연속 일수입니다.)
- **메타 업적**은 서로를 조건으로 쓸 수 있고, 더 이상 바뀌지 않을 때까지 반복 계산합니다. 순환 참조는 달성되지 않을 뿐 오류는 나지 않습니다.
  업적을 삭제하면 그 업적을 조건으로 쓰던 `meta_list`에서 자동으로 빠집니다.
- **잘못된 조건**(목표 0, 빈 태그, 한 주 8일 등)은 저장할 때 막고, 이미 저장된 경우에는 달성되지 않은 채 "조건 확인 필요"로 표시합니다.

## 4. 기록하기 화면

기록이 어떤 업적에 어떻게 반영되는지 기록하는 순간에 알 수 있게 했습니다 (`src/components/RecordEditorModal.jsx`).

| 동작 | 설명 |
|------|------|
| 단위 자동 채움 | 새 기록은 카테고리 기본값(설정한 경우) → 그 카테고리 업적이 쓰는 단위 순으로 단위를 채웁니다. 러닝에 "5"만 적어도 5km로 저장돼요. |
| 값 입력 | `1,000`처럼 쉼표를 써도 되고, `5km`·`3만원`처럼 단위를 붙여 적으면 단위 칸으로 옮겨 줍니다. 음수는 받지 않습니다. |
| 단위 안내 | 적은 단위를 업적 단위로 바꿀 수 없으면(수영에 '분') 어떤 업적에 반영되지 않는지 경고하고, 단위를 비웠을 때 어떤 단위로 계산되는지 알려 줍니다. |
| 상위 카테고리 안내 | 하위 카테고리가 있는 카테고리에 바로 기록하면 하위 카테고리 업적에는 반영되지 않는다고 알려 주고, 하위 카테고리를 바로 고를 수 있습니다. |
| 달성 미리보기 | 저장하면 달성할 업적(숨김 업적은 이름을 가림), 수정하면 다시 잠기는 업적, 가까워지는 업적과 진행도를 입력하는 대로 보여 줍니다. |
| 닫기 확인 | 입력한 내용이 있으면 닫기 전에 버릴지 묻습니다. |
| 사진 링크 | `http://`·`https://` 링크만 받습니다. |

값 없이 단위만 있는 기록은 단위를 저장하지 않고, 카테고리에서 처음 쓴 단위는 그 카테고리의 기본 단위로 기억합니다.

## 6. 업적 정의 형식 (저장 형식 v2)

```js
{
  id: 'ach-run-004',
  title: '하프 마라톤',
  description: '한 번에 21.1km를 달려 보세요.',
  categoryId: 'cat-running',        // null이면 모든 기록
  tier: 'platinum',                 // bronze | silver | gold | platinum | diamond
  condition: { type: 'single', target: 21.1, unit: 'km' },
  isHidden: false,                  // 달성 전까지 이름·설명을 가림
  manualEarnedAt: '2026-09-26',     // manual 조건일 때만
}

// 새 조건의 예
{ type: 'days', target: 30, minValue: 10000, unit: '걸음' }        // 만 보 걸은 날 30일
{ type: 'streak', target: 7, minValue: 2, unit: 'L' }              // 하루 2L 이상 7일 연속
{ type: 'count', target: 10, minValue: 60, unit: 'kg' }            // 60kg 이상 기록 10번
{ type: 'period_streak', period: 'week', target: 12, minDays: 3 }  // 주 3일 이상 12주 연속 (period: week | month)
{ type: 'period_cumulative', period: 'month', target: 100, unit: 'km' } // 한 달 합계 100km (period: week | month | year)
{ type: 'category_count', target: 7 }                               // 카테고리 7곳에 기록
{ type: 'meta_count', target: 20, minTier: 'gold' }                // 골드 이상 업적 20개
```

앱 전체 상태는 `{ categories, records, achievements, prefs, catalogVersion }` 하나로 저장합니다.
`catalogVersion`은 이 상태가 몇 번째 기본 업적 목록까지 반영됐는지입니다(8장).

### 목록을 만든 규칙

`src/data/achievements.test.js`가 아래 규칙을 검사합니다.

- **모든 말단 카테고리**에 첫 기록 업적과 5개 이상의 목표를 둡니다. 목표는 횟수, 기록한 날, 연속 기록, 매주·매달 꾸준함,
  값 목표(한 번에·누적·하루·기간 합계), 태그 목표를 섞어서 한 가지 방식에 쏠리지 않게 했습니다.
- **카테고리마다 값의 단위는 하나**입니다(그 카테고리와 상위 카테고리의 업적을 통틀어). 단위 없이 남긴 "5"가 어떤 업적에서는 5km,
  다른 업적에서는 5분으로 읽히는 일이 없게 하려는 규칙입니다.

  | 단위 | 카테고리 |
  |------|----------|
  | km | 러닝, 등산, 사이클링 |
  | m | 수영 |
  | kg | 근력 운동(3대), 벤치 프레스, 스쿼트, 데드리프트 |
  | 개 | 푸시업, 턱걸이, 감사 일기, 청소·정리 |
  | 초 | 플랭크 |
  | 분 | 요가·필라테스, 언어(영어·일본어·중국어·스페인어), 명상, 반려동물 |
  | 시간 | 수면, 강의, 공부, 디지털 디톡스, 음악, 코딩, 봉사활동 |
  | 걸음 · L · 페이지 · 자 · 장 · 문제 · 명 · 박 · 원 | 걷기 · 수분 섭취 · 독서 · 글쓰기 · 그림 · 알고리즘 · 네트워킹 · 여행(국내·해외·캠핑) · 재정(투자·저축)·기부 |

- 태그 업적은 설명에 태그를 그대로 적고(`'우중런' 태그를 붙여 보세요`), 기록하기 화면의 추천 태그로 나타납니다.
- 숨김 업적의 설명은 달성했을 때 보이는 축하 문구로 씁니다.
- 제목은 서로 겹치지 않고, 편집 화면 제한(40자) 안에 들어갑니다.
- 실제 기준을 따른 업적: 원판 1~6판(20kg 봉 + 한쪽 20kg씩), 3대 200~600, 트라이애슬론(수영 1.5km·자전거 40km·달리기 10km)과
  철인 3종 풀코스(3.8km·180km·42.195km), 국토종주·4대강 자전거길, 산악형 국립공원 18곳, 남한 3대 고봉, 불수도북, 한양도성 내사산,
  국내 3대 마라톤·세계 7대 마라톤, 조선 5대 궁궐, 17개 시·도, 국립중앙박물관과 지역 국립박물관 13곳, 국립현대미술관 4관,
  신 7대 불가사의, 헌혈유공장(은장 30회·금장 50회), JLPT·HSK·DELE.

## 8. 업데이트와 기존 데이터

기본 카테고리와 업적은 각자의 저장 데이터 안에 들어 있기 때문에, 목록이 바뀌어도 그냥 두면 기존 사용자에게는 보이지 않습니다.
그래서 저장 데이터에 `catalogVersion`을 두고, 앱이 가진 목록(`CATALOG_VERSION`)보다 오래된 데이터를 열면
`upgradeCatalog()`(`src/lib/appState.js`)가 그 데이터가 받았던 목록의 스냅숏(`src/data/catalogHistory.js`)과 비교해 합칩니다.

| 경우 | 처리 |
|------|------|
| 사용자가 없는 새 기본 카테고리 | 상위 카테고리가 있으면 추가 (새 카테고리는 기존 카테고리 뒤에) |
| 사용자가 지운 기본 카테고리 | 다시 만들지 않음 — 그 안에 들어갈 새 업적과 하위 카테고리도 추가하지 않음 |
| 기본 이름 그대로인 카테고리 | 새 이름으로 바뀜 (식사 준비 → 요리). 사용자가 바꾼 이름은 그대로 |
| 고치지 않은 기본 업적 | 새 버전으로 바뀜 (예: 철각 설명, 자격증 취득) |
| 사용자가 고친 기본 업적, 직접 만든 업적 | 그대로 |
| 사용자가 지운 기본 업적 | 다시 만들지 않음 |
| 새 기본 업적 | 카테고리가 있으면 추가. 다른 업적을 묶는 업적은 묶을 업적이 모두 있을 때만 |
| 기록, 설정 | 그대로 |

업그레이드한 뒤 처음 열 때 "새 카테고리 N개와 업적 M개가 추가됐어요" 안내가 한 번 뜹니다. 옛 형식(v1) 데이터와 예전 백업 파일도 같은 방식으로 옮겨집니다.
어떤 기본 업적을 고쳤는지는 필드 지문(`src/lib/fingerprint.js`)으로 판단합니다.

### 기본 목록을 바꿀 때

1. 바꾸기 전에 `npm run catalog:snapshot`을 실행해, 출력된 스냅숏을 `CATALOG_SNAPSHOTS`에 붙여 넣습니다(지금 버전 번호로).
2. 목록을 고치고 `CATALOG_VERSION`을 1 올립니다.
3. `npm run catalog:snapshot`을 다시 실행해 출력된 digest를 `CATALOG_DIGEST`에 적습니다. digest가 맞지 않으면 테스트가 실패합니다.

업적·카테고리 id는 다른 의미로 다시 쓰지 않습니다.

## 9. 성능

업적 786개, 기록 3,300개(3년 동안 하루 3개) 기준으로 전체 계산에 약 24ms, 기록 300개면 약 7ms가 걸립니다
(날짜를 숫자로 바꿔 연속·기간을 계산하고, 카테고리별로 기록을 한 번만 나눠 둠). 기록하기 미리보기는 메모·사진 입력에는 다시 계산하지 않습니다.
업적 화면은 검색이나 카테고리 필터가 없을 때 그룹마다 20개씩 먼저 보여 줍니다.

## 10. 변경 내역

### 2026-09-26 두 번째 개편 (86개 → 786개)

**기록하기·달성 조건에서 고친 점**

| 문제 | 고친 내용 |
|------|-----------|
| 단위 칸이 비어 있어 "30"(분)이 음악 100시간 업적에 30시간으로 더해지는 등, 단위 없는 기록이 업적마다 다르게 읽힘 | 업적 단위로 자동 채움 + 카테고리마다 단위 하나로 목록 정리 + 단위를 비웠을 때 안내 |
| 바꿀 수 없는 단위(수영에 '분')로 기록해도 아무 안내가 없음 | 반영되지 않는 업적을 경고 |
| `1,000`, `5km`를 적으면 "숫자로 입력해 주세요" | 쉼표와 단위 붙여 쓰기 허용 |
| 음수 값이 누적·하루 합계를 깎음 | 입력에서 막고 계산에서도 제외 |
| 홈의 상위 카테고리(피트니스)에서 기록하면 러닝 업적에 반영되지 않는데 알 수 없음 | 안내 문구 + 하위 카테고리 선택 칩 |
| 작성 중에 바깥을 누르면 내용이 사라짐 | 닫기 전에 확인 |
| 사진 링크에 아무 글자나 저장돼 깨진 이미지가 보임 | http(s) 링크만 허용 |
| 같은 날 기록을 여러 개 남기면 "100회" 업적이 하루 만에 달성됨 | 기록한 날 수(`days`), 주·월 단위 꾸준함(`period_streak`) 조건 추가 |
| "하루 2L를 7일 연속"처럼 매일의 목표를 이어 가는 업적을 만들 수 없음 | `days`·`streak`에 하루 기준 값 추가 |
| 철각 설명("30일 연속으로 달리면서 누적 200km")이 실제 조건(두 조건을 각각 채우면 달성)과 다름 | 설명을 조건에 맞게 수정 |
| 한 번에 업적이 수십 개 달성되면 알림이 줄줄이 뜸 | 3개까지 보여 주고 나머지는 개수로 안내 |
| 카테고리를 지우면 상태의 다른 필드(`catalogVersion`)가 사라짐 | 유지하도록 수정 |
| 추천 태그·단위가 조건 묶음 안의 여러 카테고리 합산 조건을 놓침 | 묶음 안까지 확인 |

**카테고리 (33개 → 71개)**: 피트니스에 걷기·등산·수영·맨몸 운동(푸시업·턱걸이·플랭크)·요가·필라테스, 새 최상위 카테고리 건강(수면·금주·금연)·
문화생활(영화·공연·전시)·관계(가족·친구)·생활(청소·정리·반려동물), 새 하위 카테고리 식단 관리·공부·영어·중국어·감사 일기·디지털 디톡스·
캠핑·그림·사진·가계부·알고리즘·기부·헌혈, 커리어를 업무·자격증·네트워킹으로 나눔, 식사 준비 → 요리.

**업적 (86개 → 786개)**: 기존 86개의 id는 모두 유지했습니다. 바뀐 기존 업적은 철각(설명), 레벨 업(`'승진'` 태그), 자격증 취득(자격증 카테고리의 첫 기록),
밀프렙 습관 → 집밥 습관(요리 카테고리에 맞춤)입니다.

### 2026-09-26 첫 번째 개편 (39개 → 86개)

업적을 저장하던 방식에서 기록으로 계산하는 방식으로 바꿨습니다. 이전 구조는 기록을 저장하는 순간에만 같은 카테고리의 업적을 평가해
상위 카테고리 업적이 달성되지 않고, 기록을 고치거나 지워도 반영되지 않고, 나중에 만든 업적이 기존 기록을 무시하고, 연속 기록이 '오늘' 기준이고,
단위를 무시하고 더하는 문제가 있었습니다. 모든 말단 카테고리에 시작 업적을 두고, 번역투 이름과 사실 오류(한강 다리 목록 등)를 고쳤고,
레전더리 등급을 다이아몬드로 합치고 희귀도 점수를 없앴습니다.
